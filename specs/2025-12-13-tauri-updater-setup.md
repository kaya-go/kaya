# Tauri auto-updater setup

Setup notes for Kaya's auto-updater. One-time work, but kept here so the
key-handling steps don't get lost.

## Context

Kaya uses [Tauri's built-in updater](https://v2.tauri.app/plugin/updater/).
Updates are signed with Ed25519 and verified on install. The endpoint is
`latest.json` published in the GitHub release.

## Decision

- Sign with a single repo-wide key, kept out of git. Public key lives in
  `apps/desktop/src-tauri/tauri.conf.json` under `plugins.updater.pubkey`.
- Private key + password live in GitHub Actions secrets:
  `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
- `latest.json` is generated by `scripts/generate-updater-json.ts` during the
  release workflow.

## How

1. Generate the key pair:

   ```bash
   cd apps/desktop
   bun tauri signer generate -w ~/.tauri/kaya.key
   ```

2. Paste the printed public key into `tauri.conf.json`.

3. Add `~/.tauri/kaya.key` contents to GitHub secrets as
   `TAURI_SIGNING_PRIVATE_KEY` (and the password to
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`).

4. After the first published release, ensure `Updater.tsx` calls
   `checkForUpdates(true)` on startup.

## Disabling

- Remove the `updater` plugin block from `tauri.conf.json`.
- Remove the `Updater` component from `apps/desktop/src/App.tsx`.
- Drop the "Check for Updates" menu entry.

## Troubleshooting

- **"Could not fetch a valid release JSON"** — expected before the first
  published release, or if `latest.json` is missing. Don't enable the startup
  check until after the first release.
- **"Invalid signature"** — public key in `tauri.conf.json` doesn't match the
  private key used at build time, or the `.sig` files weren't uploaded.
